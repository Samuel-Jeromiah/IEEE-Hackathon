# API contract v1

**Sources of truth:**
- `backend/schemas.py` (Pydantic) defines every field.
- `contracts/examples/*.json` holds one sample per response type. It is generated by `uv run python -m scripts.export_examples`, and a test fails if the files are stale.

Change this contract only when both sessions agree (see `CLAUDE.md`).

**Running it:** start the API with `uv run python -m serving.launch --stub` to get these examples without any models. The interactive docs at `/docs` load Swagger UI from a CDN, so they need internet. They are a development aid only, not part of the demo.

|---|---|---|
| `POST /api/analyze` | multipart: `files[]`, `text`, `prompt`, `task_hint`, `request_id` | `CaseFile` |

| `GET /api/incidents` | — | `Incident[]` |
| `POST /api/incidents` | JSON `IncidentCreate` | `Incident` |
| `GET /api/incidents/{id}` | — | `IncidentReport` |
| `POST /api/incidents/{id}/sites` | multipart: `photo`, `voice`, `video`, `location_text`, `request_id` | `Site` |
| `PATCH /api/sites/{id}` | JSON `SitePatch` | `Site` |
| `GET /api/incidents/{id}/export.csv` | — | CSV (columns will follow MEMA's PIIDA and IHIDA forms) |

| `POST /api/incidents/{id}/analyze` | JSON `AnalyzePrompt` | `AnalysisResult` |

| `GET /api/info` | — | `Info` (LAN URL and a QR code) |

## Progress and streaming

The browser drives each request in three steps:
1. It creates a `request_id` (a UUID).
2. It opens `GET /api/events/{request_id}`.
3. It then posts to `/api/analyze`, or to `/sites`, with the same `request_id`.

The events arrive in this order:
- `progress` events, carrying `stage`, `pct` and `message`.
- `delta` events, carrying chunks of the answer text as it is written.
- A final `done` event, carrying `case_id`, or an `error` event.

The POST response is the full result, and it is authoritative.

## Evidence rules (all endpoints)

- **Document answers:** `doc_qa.found == true` only when `quote` was verified against the document (`match_score` ≥ 90). Otherwise the answer is "not in the document".
- **Site fields:** every `FieldValue` lists `evidence_ids`. If no verified evidence supports a value, it has `needs_review = true`.
- **Damage levels:** `Site.level` for homes is set by rules (`domain/storm/levels.py`), never directly by a model. `level_reason` names the rule and the page of the FEMA guide.
- **Costs:** `est_cost` is always entered by a person.

## Stub-mode behavior

- `/api/analyze` picks the example from the first file's extension, or from `task_hint=code`.
- A document question or guide question containing the word "pizza" returns the "not found" example. This lets the frontend show both states.
- The incident store is in memory and preloaded with the demo incident `inc_demo`, which has three sites.
